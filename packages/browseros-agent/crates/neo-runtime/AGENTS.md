# neo-runtime

Runs one script in a fresh QuickJS realm from a starting BrowserOS tab. Its context can hand out more pages; `RunOutcome` records the calls and page identities. Every page getter is a live CDP call; nothing is cached. A `goto` answer's `Request` and `Response` getters read the session's record of what the Network domain reported, which no CDP call can read again. Read `../NEO_STYLE.md` before changing anything here.

- Depends on `browseros-cdp`, `neo-runtime-spec` and ordinary crates only; `browseros-core` is never a dependency.
- `src/tabs.rs` owns the context scope, first-seen page order, and one lazy session per handed-out tab. `src/tab_calls.rs` handles page/context lifecycle. Finish shares one bounded drain across creation settlement, tasks (the run-end input releases among them), and closing-state reads, then hides the run's highlights within their own bound; late unkept creations close in the background and may be absent from the outcome. Normal tabs survive the run.
- `src/lib.rs` draws the call path; `src/bridge.rs` is the only door from JS into Rust, and `src/dispatch.rs` the only path a browser call takes.
- A browser call runs on its own tokio task and keeps its state in the run's trace (`src/progress.rs`), never in the realm, so a call the script never awaits, or one the run ends under, still has its record.
- `tests/fixtures/replies.json` pins the reply envelope for neo-sdk's tests; rewrite it with `NEO_RUNTIME_WRITE_FIXTURES=1 cargo test -p neo-runtime --lib dispatch` after a deliberate change.
- Runs need tokio's multi-threaded runtime: a synchronous getter blocks its worker with `block_in_place` while it waits for CDP.
- `src/realm.rs` embeds `../neo-sdk/dist/sdk.js`; change the SDK in `neo-sdk`, rebuild it, and commit the bundle.

- `src/network.rs` records every request with a frame (not `data:`, not a worker's) from the page watcher's Network events, the tab session's and each attached out-of-process frame session's, and ports Playwright's `crNetworkManager.ts` correlation and formulas: redirects, extra info, served-from-cache, a subresource 204's finish, header arrays, raw-header pairing, timing, sizes, HTTP version. A session keeps 256 navigation chains and 1000 other requests (an ended one dropped first); a dropped object answers an error naming both caps. `Network.enable` (`PageSession::enable_network`) goes out on a session's first `goto`, history step or navigation wait, a network listener's subscription, or `page.requests()`, and is kept for the run. Each event the log applies answers its `Happening`s, which `src/network_events.rs` turns into the context's `request`, `response`, `requestFinished` and `requestFailed` events (full `{guid, initializer}` records, only while subscribed), and which `src/network_idle.rs` (Playwright's `networkidle`: per-frame in-flight requests, the 500 ms quiet timer, child frames) counts; the watcher fires its timers and writes `networkidle` into the main frame's state and the child frames' feeds, where every `waitUntil`/`waitForLoadState` reads it. `tests/network_e2e.rs` covers a busy page, the retention cap and a clean next run. `src/navigate.rs` answers the committed document's final hop, `null` where Playwright's goto does; `src/responses.rs` serves the `Request`/`Response` commands on guids `request@<target>:<requestId>:<hop>`. When a watcher lag may have lost an event either needs, both answer an error rather than a guess or a wait that never ends. Its tests replay `tests/fixtures/network-goldens.json`, real CDP events recorded beside Playwright's answers; rewrite it with `NEO_E2E_BROWSER=… NEO_PARITY_PLAYWRIGHT=… node crates/neo-runtime/tests/network-goldens.mjs` after a Playwright or Chromium upgrade.
- `src/reads.rs` is `Frame.textContent`, `Frame.innerText`, `Frame.innerHTML` and `Frame.getAttribute` (Playwright's `_waitForFunctionOnSelector` over loop A's backoff) and `Frame.ariaSnapshot` without a selector (polls `body,frameset`, then stitches every rendered iframe's document under its node, entered through `aria-ref=eN >> internal:control=enter-frame >> body,frameset`, its refs prefixed with the iframe's path: `f7e3`, `f7f2e1`), over their own seam traits, tested with a scripted tab under paused time; `src/aria_yaml.rs` renders the snapshot as Playwright's YAML, pinned byte for byte by `../neo-runtime-injected/tests/aria-yaml-goldens.json`.
- `src/states.rs` waits for visibility's selector context, then reads once (missing/evaluation disconnect → false); `isHidden` is that read negated. `isChecked`, `isEnabled`, `isDisabled` and `isEditable` poll for a match through `reads.rs` and read one `InjectedScript.elementState` (Playwright's `_elementState`); a state the element cannot have rejects at once. All are reads without input delivery.
- `src/element_ops.rs` serves `Frame.focus`, `Frame.blur` and `Frame.dispatchEvent` (loop A, or `_waitForFunctionOnSelector` for the dispatch) and the Neo commands `neo:scrollIntoViewIfNeeded`, `neo:selectText` and `neo:boundingBox` (Playwright's `Locator._withElement` over an `ElementHandle`: one attached element, then `_retryAction`'s [0, 20, 100, 100, 500] ms backoff); focus, blur and selectText take the tab's input turn. `dispatchEvent` dispatches from the isolated world, so `eventInit` takes plain values only and Rust refuses the rest before any page call; `boundingBox` answers `DOM.getBoxModel`'s border box plus each out-of-process owner iframe's border-box origin (`Frames::border_offset`, Playwright's `_framePosition`), while input keeps aiming by the content box (`Frames::offset`). `src/highlight.rs` keeps the run's highlights per tab (`PageSession::highlights`) over the injected overlay: placed once, in the document the selector reaches, and removed from every document the run put one in by `Page.hideHighlight` and by `Dispatcher::finish` at run end, after the input releases and within a budget of its own (`HIGHLIGHTS_WAIT`). `tests/element_ops_e2e.rs` pins the refusals, the run-end removal and the box in a bordered out-of-process frame, in Playwright's numbers.
- `src/lists.rs` serves `count`, a Locator collection snapshot: `describe` rejects an invalid selector with Playwright's message, then one non-strict glue read, without waiting, target marks or call-log lines; scripted-tab tests pin values and page steps. `allTextContents` is Playwright's `$$eval`, served by `src/evaluate.rs`.
- `src/main_world.rs` is the only door to a page's own (main) world: it adopts the utility world's `document` there (`DOM.describeNode`, then `DOM.resolveNode` without a context), installs Playwright's `UtilityScript` (built `dist/utility.js`), and for Playwright's `mainWorld: true` element callbacks that world's own `InjectedScript` (built `dist/main-injected.js`, held by CDP id, never on a global), and runs only built `../neo-runtime-injected/dist/*.js` functions with `Runtime.callFunctionOn`; never `Runtime.evaluate` or `Runtime.enable` (`tests/page_js_guard.rs`). `src/evaluate.rs` is the policy over it: Playwright's evaluations, `$`/`$$`/`$eval`/`$$eval` (matches found by the utility world's selector engine, then adopted into the main world), `getProperty`, `waitForFunction`, the element callbacks (`call_on_element_main`: `ElementHandle.dispatchEvent`, `waitForFunction` on a selector), and the run's JS handles (`handle@<run token>.<n>`, one object group per session per run, released when the run ends).
- `src/waits.rs` owns selector, URL and lifecycle waits over one loop and the input-free `WaitTab` seam; navigation waits use buffered commits and lifecycle counts, DOM waits use loop A's backoff, and `Progress` owns every deadline and cancellation. A child frame's URL and load-state waits run the same loop over that frame's feed (`page.rs` `FrameFeeds`), written by the tab's watcher and by a watcher started on each OOPIF host session; the wait refinds the frame's host after a process swap, and a removed frame (or one gone with the page's document) ends it with `Frame was detached`.
- `src/history.rs` is Playwright's server `waitForNavigation` and what waits on it: `Page.reload`, `goBack` and `goForward` (served protocol commands) and the `neo:waitForNavigation` / `neo:nextNavigation` / `neo:finishNavigation` / `neo:releaseNavigation` frame commands. A URL-predicate wait is a cursor in the run's `Cursors`: the realm keeps one next waiting while it tests each navigation's predicate on its own, a finish names the navigation it accepted, and every exit (finish, release, a failed step) ends the cursor. A finish or release claims its cursor at admission and skips the dispatcher's in-flight caps (the cursor cap bounds them), and every call gives its in-flight share back just before its reply is sent. The page watcher (`page.rs` `apply_frame`) tracks Playwright's pending document, so a navigation whose request fails is a navigation event with its error, and a back-forward cache restore counts as loaded at its commit. Tested against a scripted tab under paused time, and on a real browser with the cache on in `tests/history_e2e.rs`.
- `src/click.rs` is the policy of Playwright's pointer actions, `Frame.click`, `dblclick`, `hover` and `tap` (Playwright's two retry loops, every call-log line, one `PointerAction` per method: its states, its hit-target interceptor kind and its input) over the `Tab` seam; `src/page.rs` implements the seam over CDP, and `src/world.rs` calls the injected glue. Click policy is tested against a scripted `FakeTab` under paused time (what a click calls, in which order, and what it delivers; never log wording or retry counts); the mechanism against `tests/support/fake_browser.rs` (`tests/click_lifecycle.rs`).
- `src/events.rs` is the run's event pipe (Playwright's server-to-client event messages): one ordered queue drained by the realm before each reply's caller continues (watermark W after a watcher flush barrier, skipped when nothing is subscribed) and on an idle wake. `src/page_events.rs` turns the page watcher's CDP events into console, pageError, dialog, dialogClosed, close and crash events; `src/console.rs` holds Playwright's console text and `exceptionToError` formulas and the history `consoleMessages()` reads; `src/dialogs.rs` the tab's dialogs and `Dialog.accept/dismiss`. `Runtime.enable` happens only for a run that listens to console messages or page errors, or reads their history; its replay is history only. `tests/events_e2e.rs` covers the pipe on a real browser. `src/downloads.rs` serves the run's downloads (the `download` event and `Download`'s `Artifact` commands on `download@<guid>`): while a run listens, the browser reports downloads it saves itself (`Browser.setDownloadBehavior` `default` with events), and `src/switch.rs` counts the `Runtime`'s runs holding that and target discovery, connection settings they share; `tests/downloads_e2e.rs` proves the reports end with the last run and the user's downloads save as before. A `filechooser` listener intercepts the page's file choosers, out-of-process frames' too, until the last one goes (`page_events.rs`, `tests/file_chooser_e2e.rs`).
- `src/capture.rs` serves `Page.screenshot`, `Page.pdf`, `ElementHandle.screenshot` (on the handle's own node, adopted into its frame's utility world) and Neo's `neo:screenshot` (behind `locator.screenshot`). `src/screenshot.rs` ports Playwright's `Screenshotter` and `CRPage.takeScreenshot`: its page-side steps are glue calls in each frame's utility world, and their cleanup (restore, masks, background) runs on the run's tracker even when the call stops. `src/pdf.rs` ports `CRPDF` (`Page.printToPDF` read as a stream). A `path` option writes only inside the run's artifact directory (`RunRequest::artifacts`, `src/artifacts.rs`, listed in `RunOutcome::artifacts`); a binary result over 16 MiB is refused, the realm's measured limit.
- `src/browser_calls.rs` is the run's `Browser` (`browser@default`), the BrowserOS it is attached to: `browser.newContext` makes an isolated context (`Target.createBrowserContext`) whose pages are ordinary entries of the run's registry, tagged with their context (`PageEntry::context`). Its `disconnect` is the browser's `close` and the run's own context's (a connectOverCDP default context closes by closing its browser): the run's subscriptions end, its other calls stop, a pending creation settles and every context the run created is disposed, its own tabs left open. `Dispatcher::finish` (or a dropped run's `Drop`) disposes the rest. It never launches or closes a browser. `src/emulation.rs` keeps each page's viewport and media for the run on its session (`PageSession::emulation`) and applies a created context's options to each of its pages before the first call on it, and (paused auto-attach, as Playwright) to each out-of-process frame of such a page before it runs; Chromium drops a session's overrides when it detaches, so emulation lasts for the run. `src/debugger.rs` is `context.debugger`: `Dispatcher::call` asks it, in call order, whether a call waits before it starts. `tests/platform_e2e.rs` and `tests/platform_review_e2e.rs` cover run-end disposal (also on cancellation and a dropped run) and the emulation's lifetime on a real browser.
- `src/set_input_files.rs` serves `setInputFiles` (Locator, Page, Frame): Playwright's preparation once (payloads typed by name with `src/mime.rs`, the `mime` 4.1.0 package's own tables in `vendor/mime/`), then loop A around the per-element action `SetInputFiles` (also for a fixed element), with no actionability and no input turn: the `fileInput` glue retargets to the input and throws Playwright's errors, payloads go through `InjectedScript.setInputFiles`, paths through `DOM.setFileInputFiles` (a directory after arming its `input` event). A path names a file or directory inside the run's artifact directory only (`Artifacts::existing`), where Playwright's client stats any host path. `src/drop_on.rs` serves `Locator.drop`: the same preparation, local files read into payloads (at most 50 MiB), then loop B for the `drop` pointer action, whose perform is the `dropOn` glue (a `DataTransfer` and `dragenter`, `dragover`, `drop`) inside the tab's input turn.
- A tab has one keyboard, one mouse and one hit-target slot, shared by every call and run on it. Input to a tab takes a turn (`Tab::input`, `src/page.rs` `TabInputs`, per `Runtime` and tab) from the interceptor's setup until its stop has answered, writes included; never wait for an element while holding one. The turn holds the tab's device state (`src/input_devices.rs`: held keys and modifiers, the pointer's position, held buttons, each key and button listed once for every run that holds it, so one run's end never releases what another live run holds; a run's end first marks the run ended on every tab (`TabInput::mark_ended`, then a state-only `Retire` in its release plan; a dropped `PageSession` marks it too), so what a refused, failed or cut-off release leaves is a dead hold, held by no live run, and goes at the next run's end; the mark is forgotten only between turns once the run holds nothing (`InputDevices::forget_ended`), so a late answer or a restore within a turn records a dead hold too, and an ended run's writer writes only what it owes; `page.rs` `tests_that_random_interleavings_of_input_and_run_ends_leave_nothing_held` checks 3000 seeded schedules), which only a held turn reaches: every input call plans its events from it (`Plan`; `keyboard.type`'s text a chunk at a time, as the writer reaches it), and the one input writer (`write_plan`) sends a plan, writes every owed release even after a cancel or a CDP error (with the modifiers and buttons the tab actually holds then), keeps writing a run end's releases past a failed one, applies each event's effect as it is written, and reports `Done` only for a complete plan. Chromium's drag manager lives in the same writer: a move that is not a click's runs Playwright's intercept protocol while the left button is held (`InputSender::move_intercepting_drag`, glue drag listeners in every frame), and while a drag runs (`InputDevices::drag`) moves are `dragOver`, a release drops and Escape cancels; `src/drag.rs` serves `dragAndDrop` as two pointer actions (move and down, move and up) in one progress. `src/devices.rs` serves `page.keyboard`, `page.mouse` and `page.touchscreen` over it; `Dispatcher::finish` releases what a run left held, on one task per tab of the run's tracker that no budget cuts off and that waits for no other cleanup (`Tabs::release_input`). State transitions are tested with a recording sender under paused time.

- Every constant, and every value, step or message ported from Playwright, carries a provenance line (`Playwright:`, `Deviation:`, `Neo:`, `Platform:` or `Unexplained:`); `cargo test -p neo-runtime --test provenance` checks each line against Playwright vendored under `vendor/playwright/`, and regenerates `../NEO_DEVIATIONS.md` with `NEO_RUNTIME_WRITE_FIXTURES=1` (`../NEO_STYLE.md`, Provenance).

Checks, from `packages/browseros-agent`: `scripts/neo-check.sh`. The end-to-end tests need a browser and skip without one:

```sh
export NEO_E2E_BROWSER="/Applications/BrowserOS neo.app/Contents/MacOS/BrowserOS neo"
cargo test -p neo-runtime --test tabs_e2e --test sync_getters --test click_e2e --test navigation_e2e \
  --test reads_e2e --test states_e2e --test acceptance_e2e --test waits_e2e --test frames_snapshot_e2e --test frames_waits_e2e \
  --test events_e2e --test history_e2e --test platform_e2e --test platform_review_e2e -- --nocapture
```

Try a script by hand with `cargo run -p neo-runtime --example neo_run -- --help`.

Live website scenarios are in `integration-tests/`, registered in Cargo.toml. They are ignored
by default; their module docs give opt-in commands. They use temporary profiles, including for
Amazon's anonymous cart write, and keep one Rust `Runtime` across submitted scripts.
