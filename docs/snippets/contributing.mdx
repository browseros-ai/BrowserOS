BrowserOS neo has two main parts you can contribute to:

- **Agent platform** — The cockpit new tab, the MCP surface agents connect to, and session replay (TypeScript, React, Rust)
- **Browser** — The custom Chromium build (C++/Python)

Most contributors work on the agent platform since it's much easier to set up.

## Path 1: Agent Platform Development

The agent platform lives in `packages/browseros-agent`. BrowserOS neo is two pieces that run together:

| Component | Path | What it does |
|-----------|------|--------------|
| **Cockpit** | `apps/claw-app` | WXT + React extension — the new tab where you watch agents work, replay sessions, and manage connections |
| **Server** | `apps/claw-server` | Rust backend — the MCP endpoint agents connect to, plus the API behind the cockpit |

`claw-server` builds on the shared Rust crates in `crates/`. The wire types are generated on both sides from one contract: `packages/claw-api` and `packages/claw-api-client` on the TypeScript side, the `claw-api` crate on the Rust side.

### Prerequisites

- [Bun](https://bun.sh/docs/installation), the only supported package manager and runtime. The version is pinned in `package.json`.
- Go, for the dev supervisor
- Rust, via `rustup`
- [BrowserOS neo](https://cdn.browseros.com/download/BrowserOS_neo.dmg) installed, since the supervisor launches it

The dev loop is macOS only today. Linux and Windows contributors can install dependencies and run the checks.

### Setup

```bash
# Clone the repo
git clone https://github.com/YOUR-USERNAME/BrowserOS.git
cd BrowserOS/packages/browseros-agent

# Install dependencies
bun install

# Copy the environment file (everything in it is optional for a first run)
cp .env.development.example .env.development
```

### Running Locally

```bash
bun run dev:claw:watch:new
```

This starts the cockpit with hot reload, its web preview, and `claw-server`, then launches BrowserOS neo against them on random ports with a fresh profile. The Rust server restarts whenever its sources change. Stop everything with `bun run dev:stop`.

Use `bun run dev:claw:watch` instead to keep a persistent dev profile on fixed ports.

### Commands

| Command | Description |
|---------|-------------|
| `bun run dev:claw:watch:new` | Run the cockpit and server against a fresh profile |
| `bun run dev:claw-onboard` | Run the onboarding flow on its own |
| `bun run check` | Lint, typecheck and Fallow |
| `bun run test` | TypeScript test suites |
| `bun run test:rust` | Rust workspace tests |
| `bun run lint:rust` | Clippy, warnings are errors |
| `bun run fmt:rust` | rustfmt check |
| `bun run codegen:claw-api` | Regenerate the wire types after an API contract change |

The full guide is [`packages/browseros-agent/CONTRIBUTING.md`](https://github.com/browseros-ai/BrowserOS/blob/main/packages/browseros-agent/CONTRIBUTING.md).

## Path 2: Browser Development

Only go down this path if you're working on Chromium-level features like patches to the browser itself.

**Requirements:**
- ~100GB disk space
- 16GB+ RAM recommended
- 3+ hours for first build

### Prerequisites

<Tabs>
  <Tab title="macOS">
    - macOS with Xcode and Command Line Tools

    - [UV](https://docs.astral.sh/uv/) (Python package manager)
    - Git
  </Tab>
  <Tab title="Linux">
    - Ubuntu 20.04+ or similar
    - build-essential package
    - Python 3.12+
    - [UV](https://docs.astral.sh/uv/)
    - Git
  </Tab>
  <Tab title="Windows">

    - Git
  </Tab>

### Build Instructions

**1. Clone Chromium source**

Follow the official [Chromium: Get the Code](https://www.chromium.org/developers/how-tos/get-the-code/) guide. This sets up `depot_tools` and fetches ~100GB of source code.

Note the path where you clone it (e.g., `~/chromium/src`).

**2. Install UV and dependencies**

```bash
# Install UV
curl -LsSf https://astral.sh/uv/install.sh | sh

# Navigate to build system
cd packages/browseros

# Install dependencies
uv sync
cp .env.example .env
```

**3. Build a debug version**

```bash
uv run browseros build --preset debug --product browserclaw --chromium-src <your-chromium-src-path>
```

To see exactly what a build would run without running it:

```bash
uv run browseros build --preset release --show-plan
```

`browseros build` produces one binary for one product on one platform. For the full picture, read [`packages/browseros/bos_build/README.md`](https://github.com/browseros-ai/BrowserOS/blob/main/packages/browseros/bos_build/README.md).

### Troubleshooting

**Build fails with missing dependencies** — Make sure you followed all steps from the Chromium build guide for your platform.

**Out of disk space** — Chromium needs ~100GB. Check with `df -h`.

**Build takes too long** — Use ccache, more CPU cores, or stick to debug builds.

**UV command not found** — Restart your terminal after installing UV.

## Making Your First PR

1. **Fork** the repository on GitHub
2. **Clone** your fork locally
3. **Create a branch**: `git checkout -b feature/your-feature`
4. **Make changes** and test them
5. **Commit**: `git commit -m "feat: add your feature"`
6. **Push**: `git push origin feature/your-feature`
7. **Open a PR** with a [Conventional Commits](https://www.conventionalcommits.org/) title and a clear description

### Sign the CLA

On your first PR, our bot will ask you to sign the Contributor License Agreement. Just comment:

```
I have read the CLA Document and I hereby sign the CLA
```

## Code Standards

**TypeScript:**
- Use Bun for everything: `bun install`, `bun test`, `bun run <script>`
- Use extensionless imports: `./utils`, not `./utils.js`
- Use kebab-case for folders and multi-word non-component files
- Keep shared constants in `@browseros/shared` instead of scattering magic values
- Lint and format with Biome; `bun run lint:fix` applies what it can

**Rust:**
- Clippy with warnings as errors, and rustfmt

**General:**
- Keep comments minimal: hidden constraints, subtle invariants, surprising behavior
- Write tests for new features
